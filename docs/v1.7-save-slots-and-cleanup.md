## 1. Season-advance bug fix

### Root cause
`src/data/mockTeams.ts:54`:

```ts
export const advancePlayerToYear = (_player: Player, _year: number): Player | null => null;
```

`advanceSeason` (in `store/leagueStore.ts`) maps every player through this
function, treats `null` as "retired", and rebuilds rosters from the survivors.
With the stub returning `null` for everyone, every player retires and every
team is empty going into the new season.

### Fix
Replace the stub with a real implementation that:

- Returns the same `Player` with all season-state reset:
  - `seasonStats` zeroed (every numeric field → 0).
  - `stamina` set to 99 (full recovery between seasons).
  - `injuryWeeksRemaining` → 0.
  - `suspensionMatches` → 0.
  - `forSale` → `false`.
- Returns `null` only when the player should retire (see retirement model
  below).
- Increments anything age-derived implicitly. The runtime `Player` has
  `birthYear` (immutable), so age is derived as `nextYear - birthYear`. No
  explicit "age" field to bump.

### Retirement model

Compute `nextAge = nextYear - player.birthYear`.

| Position group | Soft retirement starts | Hard retirement |
|---|---|---|
| `POR` (goalkeepers) | 38 | 42 |
| All others | 35 | 38 |

Soft / hard rules:

- **Below soft age** → never retires.
- **Soft ≤ age < hard** → retires with probability
  `(age - soft) / (hard - soft) * 0.6`.
- **age ≥ hard** → always retires.

Deterministic seed: use a hash of `player.id + nextYear` so the same player
always retires on the same year regardless of save-restore cycles. Easiest
implementation: a small mulberry32 / sfc32 seeded by a numeric hash of the
string. Avoid `Math.random()` so reloads don't churn rosters differently each
time.

Helper file (new): `src/engine/retirement.ts`. Exports:

```ts
export const SOFT_RETIREMENT_AGE = { POR: 38, default: 35 } as const;
export const HARD_RETIREMENT_AGE = { POR: 42, default: 38 } as const;
export function shouldRetire(player: Player, nextYear: number): boolean;
export function advancePlayer(player: Player, nextYear: number): Player | null;
```

Then `mockTeams.ts:advancePlayerToYear` becomes a one-line re-export wrapper
to keep import sites stable:

```ts
export { advancePlayer as advancePlayerToYear } from '../engine/retirement';
```

### Retirement record format
`advanceSeason` already builds a `TransferRecord` with `kind: 'retirement'`
for every retired player and surfaces them in the transfer log. No format
change needed — just make sure the new code path still routes through that
branch when `shouldRetire` returns true.

### Tests
- Run the project, finish a full season (sim every jornada), advance, confirm
  teams are not empty.
- Inspect a 22-man squad: ~1–3 retirements per team is normal; 22 is the bug.
- Check that an under-35 squad has 0 retirements.
- Check that a 37-year-old field player has roughly a 40% chance of retiring,
  and that the result is stable across reloads (deterministic seed).

## 2. Multi-league save slots

Today: one league lives at `localStorage['openfutbol_league']`. Backup &
restore work but there's only one slot.

### Data model

Keep the existing single-slot key as the **active** slot for backward compat.
Add namespaced slot keys:

```
openfutbol_slot_index            — JSON array of slot metadata (see below)
openfutbol_slot_active           — id of the currently-loaded slot (or null)
openfutbol_slot_<slotId>         — LeagueState JSON for that slot
openfutbol_league                — mirror of the active slot (kept in sync for the
                                   existing autosave-on-tick path; on first
                                   load with no slot index, we adopt this as
                                   slot "default" so existing players don't
                                   lose their game)
```

`slotId` is a UUID-ish string (`crypto.randomUUID()` is fine — already widely
supported).

Slot metadata entry shape:

```ts
interface SaveSlot {
  id: string;
  name: string;            // user-facing label, default "Carrera de <team>"
  createdAt: string;       // ISO timestamp
  updatedAt: string;       // ISO timestamp
  // Snapshot of LeagueState for the picker UI — avoids loading the full state.
  summary: {
    gameMode: 'standard' | 'promanager' | 'fantasy';
    seasonYear: number;
    currentJornada: number;
    userTeamId: string | null;
    userTeamName: string | null;
    leaguePosition: number | null;
    managerName: string | null;
  };
}
```

### New module: `src/store/saveSlots.ts`

```ts
export function listSlots(): SaveSlot[];
export function getActiveSlotId(): string | null;
export function loadSlot(slotId: string): LeagueState | null;
export function saveSlot(slotId: string, state: LeagueState, name?: string): SaveSlot;
export function renameSlot(slotId: string, name: string): void;
export function deleteSlot(slotId: string): void;
export function createSlotFromCurrent(state: LeagueState, name?: string): SaveSlot;
export function setActiveSlot(slotId: string | null): void;
export function migrateLegacyKey(): void; // one-shot, runs on first boot v1.7+
```

Migration on first v1.7 boot: if `openfutbol_slot_index` is missing **and**
`openfutbol_league` exists, create a slot called "Carrera principal" with a
fresh UUID, persist the league to that slot, set it active, write
`openfutbol_slot_index`. Subsequent boots just `loadSlot(activeId)`.

### App.tsx integration

- On boot, after `getInitialLeagueState` fallback chain, also call
  `migrateLegacyKey()` and then `loadSlot(getActiveSlotId())`.
- The existing autosave effect (`setItem('openfutbol_league', JSON.stringify(league))`)
  expands to also write `openfutbol_slot_<activeId>` and refresh the slot
  summary timestamp + standings position.
- `handleMatchEnd`, `advanceSeason`, and any place that mutates `league`
  already trigger that effect via state change — no manual save needed.

### UI: extend `BackupView`

Add a new section above the existing Export / Import / Reset blocks:

```
┌──────────────────────────────────────────────────────────┐
│ PARTIDAS GUARDADAS                                       │
├──────────────────────────────────────────────────────────┤
│ • Carrera principal — Real Madrid, J18, 2026/27   [►][✎][✕] │
│ • Anderlechazo grind — Anderlechazo, J5, 2026/27  [►][✎][✕] │
│ • Suplente liga belga — RFC Lieja, J22, 2025/26    [►][✎][✕] │
│                                                          │
│ [+ NUEVA PARTIDA DESDE CERO]   [↑ IMPORTAR ARCHIVO]      │
└──────────────────────────────────────────────────────────┘
```

- `►` = cargar (replaces current league, sets active)
- `✎` = renombrar (inline edit)
- `✕` = borrar (confirm modal)
- "Nueva partida" routes to the existing PLAY flow but tags the resulting
  game with a fresh slot id immediately so it autosaves to a new slot.
- "Importar archivo" opens the existing JSON picker but lands the result in
  a new slot, not replacing the current one.
- The currently-active slot has a magenta `★` marker on the left and is
  visually highlighted (e.g. `border-vga-magenta`).

Export per slot: the existing Exportar button keeps working — it exports the
currently active slot. No format change to the exported JSON, but include
the slot name and `summary` in the wrapper so re-import can use it.

### Style

Same dark-panel language as MatchScreen / SquadViewCompact: `bg-vga-black`,
thin `border-vga-blue`, magenta panel titles (`text-vga-magenta` `text-[9px]
uppercase tracking-widest`). Action buttons follow the existing button
treatment used elsewhere in BackupView.

### Edge cases

- LocalStorage quota: 5 MB. Each league JSON is ~200–600 KB. Realistic cap is
  ~10 slots. Show a friendly error toast if a save fails with `QuotaExceededError`
  and suggest deleting old slots / exporting to file.
- Switching slots mid-match: confirm modal warns "tu partida actual se
  guardará automáticamente". The active league is always autosaved before the
  swap.
- Deleting the active slot: load the most recent remaining slot, or reset
  to the main menu if no slots remain.

## 3. Stats-pack rebrand (remove every FIFA reference)

### Scope

Strip all in-repo references to "FIFA" from:

- TypeScript identifiers, types, file names, imports
- Strings in i18n files, in-component literals, comments
- Documentation files
- Scripts under `scripts/` (or delete them if FIFA-specific)
- UI badges (PlayerCard "F22" badge, PlayerDetailView "FIFA 22" pill, tooltip

Replacement language:

- Internal identifier: `statsPack` / `StatsPack` / `StatsEntry`

## 6. Implementation order

Do this strictly top-down so each step ships a working build:

1. Bug fix: `engine/retirement.ts` + `advancePlayerToYear` rewrite. Build.
2. Manual run-through: start a game, end-of-season, confirm rosters survive.
3. Stats-pack rebrand. Find/replace + UI tweaks. Build + typecheck.
4. Save slots: data layer (`store/saveSlots.ts`) first, then BackupView UI.
5. Migration: boot logic in `App.tsx` so existing players land on a slot
   automatically with no data loss.
6. Changelog + help guide content.
7. Version bump + header label sync.
8. Final build, manual smoke test of every major flow:
   - Boot fresh (clear localStorage) → main menu → Play → finish a match → finish a season → confirm next year is populated.
   - Boot with old save key only → confirm it's migrated to slot "Carrera principal".
   - Save 3 slots, switch between them, rename one, delete one, import a JSON, export a slot.
   - ProManager: start a career, advance season, confirm offers and reputation still work.
